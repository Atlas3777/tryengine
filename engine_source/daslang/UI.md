# Игровой UI

Retained UI на daslang: узлы (виджеты) живут между кадрами, но **объявляются заново каждый
кадр**. Скрипт описывает, что должно быть на экране; движок находит узел по 64-битному id,
переносит на него прошлое состояние (hover/press/анимации), раскладывает дерево и строит
команды отрисовки. Геометрию глифов и квадов строит C++-проход `UiPass`, поэтому в скрипте нет
ни одной вершины.

## Слои

| Слой | Где | Отвечает за |
| --- | --- | --- |
| Виджеты | `engine_source/daslang/Ui.das` | `Panel`, `Label`, `Button`, `Slider`, ...; id, layout, hit-test, состояния, команды |
| Типы | `engine_source/daslang/UiTypes.das` | `UiStyle`, `UiLayout`, `UiTheme`, `UiButtonTemplate`, `UiDrawCmd`, easing и цвета |
| Тема игры | `game/scripts/UiTheme.das` | цвета, размеры, шаблоны кнопок, имена звуков — «как выглядит» |
| Составные виджеты игры | `game/scripts/UiWidgets.das` | повторяющиеся пары/группы виджетов: `StatRow`, `MeterRow` |
| Экраны игры | `game/scripts/Screen*.das` | по файлу на экран (`main_menu`, `hud`, `pause`, `shop`): `Draw(assets : AssetMap)`, «что и где стоит» |
| Навигация | `game/scripts/GameScreens.das` | стек `ScreenRef` и политика поверх него (никогда не пустой) |
| Boot/манифест | `game/scripts/GameUi.das` | boot-запрос меню, восстановление после горячей перезагрузки, `Frame()` |
| Состояние экранов | `game/scripts/GameState.das` | hp/gold/volume, общие подписи, флаг паузы |
| Поток сцен | `game/scripts/GameFlow.das` | загрузка сцены из главного меню, `IsReady` для `GameUpdate` |
| Биндинги | `engine_source/graphics/src/Module_Ui.cpp` | измерение текста, размер окна, таблица строк кадра |
| Проход | `engine_source/graphics/src/UiPass.cpp` | вершины, батчи, scissor, блендинг, SDF-текст |

Правило разделения: **виджеты повторяются, экраны уникальны**. Виджет — функция модуля `Ui`;
экран — функция модуля игры `def public Draw(assets : AssetMap)`. Ни реестра, ни имён: экран
опознаётся указателем на функцию. Стили не живут ни там, ни там: они в теме.

## Кадр

```
Begin()        время кадра (свой клок UiClock), ввод, hit-test, анимации, новый список команд
объявление     виджеты: Ui::Panel/... находят или создают узлы под текущим родителем
End()          layout (measure снизу вверх, arrange сверху вниз), emit в команды,
               sweep узлов, которых не было в этом кадре, и только потом — колбэки и звуки
```

Обёртки: `Ui::Frame() { ... }` (Begin + блок + End), `Ui::FrameScreen(ref)` (Begin + один
`ScreenRef` + End), `Ui::Begin()`/`Ui::End()` вручную. Ранний `return` из блока `Frame` оставляет кадр
открытым: следующий `Begin` это диагностирует и начнёт заново, но лучше так не делать.

Колбэки и звуки выполняются в `End`, после того как дерево построено и нарисовано. Поэтому
изменять состояние игры в `@@`-действии безопасно, но `Pulse` по id из колбэка уже не
попадёт в узел: id скопирован именем экрана. Просите пульс флагом в объявлении (так делает
`ScreenHud.das`).

## Как этим пользоваться

```das
// Экран: функция с картой ассетов своего бандла. Карта — дескриптор из callback загрузчика.
def public Draw(assets : AssetMap) {
    Ui::Panel("##hud", UiTheme::kHudPanel, UiLayout(offset = float2(24.0f, 24.0f), spacing = 8.0f)) {
        Ui::Label("##hp", "HP {int(g_state.hp)} / {int(g_state.hp_max)}", UiTheme::kMuted)
        Ui::ProgressBar("##hpbar", g_state.hp / g_state.hp_max, "", UiTheme::kHpBar)
        Ui::Row("##buttons", UiStyle(), UiLayout(spacing = 8.0f)) {
            Ui::Button(UiTheme::kPrimaryButton, "##fire", "Fire", @@OnFire)
            Ui::Button(UiTheme::kDangerButton, "##damage", "Damage", @@OnDamage)
        }
        Ui::Slider("##volume", g_state.volume, 0.0f, 1.0f)   // пишет назад в переменную
    }
}

// Показать: указатель на функцию + карта ассетов (её приносит Loader::MapOf).
GameScreens::Show(Ui::ScreenRef(build = @@Draw, assets = loaded_map))
```

`loaded_map` — `AssetMap` из `Loader::MapOf(maps, kBundle)`; экран не читает диск и не ищет
путь. Загрузчик уже принёс бандл экрана и его родителя.

`@@OnFire` — указатель на функцию, как в пожелании `button("##fire", @@OnFire)`: функция не
захватывает контекст (иначе daslang пришлось бы держать замыкание в узле, а он живёт дольше
кадра). Всё, что нужно действию, лежит в глобальных переменных модуля.

## Id и состояние

`id = mix(parent, mix(salt, fnv(local_id)))`:

- `local_id` — строка в объявлении (`"##fire"`); префикс `##` не обязателен, но `##` — привычка
  ImGui и защищает от коллизий с текстом;
- `salt` — номер элемента в `For` и имя экрана в `Screen`, поэтому одинаковый `##fire` в двух
  экранах — два разных узла;
- `parent` — узел текущего контейнера.

Отсюда правила: id уникальны среди соседей, а не во всём дереве; узел, который не объявили в
кадре, в конце кадра удаляется вместе с его hover/press-состоянием; повторное объявление
одного id среди соседей — диагностика `duplicate widget id` (один раз за кадр).

`Ui::DebugRect("##hud/##fire")` возвращает прямоугольник (диагностика и тесты), для узла внутри
экрана — `Ui::DebugRect("##fire", "hud")`.

## Layout: как верстать без опыта

Вёрстка здесь — это два простых механизма. Сначала выберите, **к какому углу родителя**
прилипает блок (`anchor` + `offset`). Потом просто **перечислите детей** — они сами встают друг
под другом (`Panel`/`Column`/`Group`) или друг за другом (`Row`). Никаких координат у отдельных
кнопок нет и быть не должно.

### Система координат

Начало — левый верхний угол вьюпорта, `x` растёт вправо, `y` вниз, всё в пикселях. В редакторе
это пиксели текстуры `SceneGameView`, а не окна: начало координат всегда `(0, 0)`, а мышь
пересчитывается через `Ui::SetInputViewport(origin, size, hovered)` (в `origin` только позиция
указателя).

У каждого узла есть одна коробка: `rect` (позиция и размер), внутри — `padding` (внутренние
поля, задаются стилем), по краю — рамка. **Margin нет**: зазор между блоками задаёт `spacing`
контейнера, а отступ от края — `offset`.

### Anchor: к какому углу прилипает блок

`anchor = float2(ax, ay)`, где каждая ось — доля от 0 до 1 внутри коробки родителя:

```
родитель (вьюпорт или панель)
+--------------------------------------------+
| (0,0)                            (1,0)     |
|   лево-верх        центр-верх   право-верх   |
|                                            |
|   лево-центр       центр        право-центр |
|                                            |
|   лево-низ         центр-низ    право-низ   |
| (0,1)                            (1,1)     |
+--------------------------------------------+
```

`offset` прибавляется **после** выравнивания, в пикселях, поэтому у правого края он
отрицательный:

```das
// левый верхний угол, 24 px от обоих краёв
UiLayout(anchor = float2(0.0f, 0.0f), offset = float2(24.0f, 24.0f))

// правый верхний: правый край прижат к правому краю, поэтому offset.x < 0
UiLayout(anchor = float2(1.0f, 0.0f), offset = float2(-24.0f, 24.0f))

// ровно по центру
UiLayout(anchor = float2(0.5f, 0.5f))

// по центру внизу, 48 px над нижним краем
UiLayout(anchor = float2(0.5f, 1.0f), offset = float2(0.0f, -48.0f))
```

Правило выбора: **какой край важнее, к тому и прилипайте**. Панель HP растёт вправо и вниз —
прилипает к левому верхнему углу. Мини-карта — к правому верхнему. Тост — к нижнему центру.
Крестик закрытия — к правому верхнему углу своего окна.

### Поток: дети встают сами

- `Panel` — фон + `padding`, дети сверху вниз;
- `Column` — то же без фона (фон можно дать стилем);
- `Group` — прозрачный контейнер, тоже сверху вниз;
- `Row` — дети слева направо;
- `Spacer` — пустое место заданного размера;
- `spacing` в `UiLayout` контейнера — зазор между детьми.

Ребёнок с ненулевым `anchor` **выходит из потока**: он не занимает место у братьев, а
позиционируется внутри контейнера (так делают крестики, бейджи, всплывашки).

### Размеры

- `size` — жёсткий размер узла; `0` означает «померить содержимое» (это дефолт);
- `grow` — доля свободного места контейнера: `grow = float2(1.0f, 0.0f)` — во всю ширину;
  две колонки по `0.5f`; `grow.y = 1.0f` — занять остаток по высоте;
- текст переносится по словам, если у `Label` задан `size.x`.

### Готовые примеры

```das
// Панель в левом верхнем углу; дети текут вниз, 8 px между ними.
Ui::Panel("##hud", UiTheme::kHudPanel,
          UiLayout(anchor = float2(0.0f, 0.0f), offset = float2(24.0f, 24.0f), spacing = 8.0f)) {
    Ui::Label("##title", "tryengine UI", UiTheme::kTitle)
    UiWidgets::MeterRow("##hp", "HP", g_state.hp, g_state.hp_max, UiTheme::kHpBar, HpText())
    Ui::Row("##buttons", UiStyle(), UiLayout(spacing = 8.0f)) {
        Ui::Button(UiTheme::kPrimaryButton, "##fire", @@OnFire)
        Ui::Button(UiTheme::kDangerButton, "##damage", @@OnDamage)
    }
}

// Текст в правом верхнем углу.
Ui::Label("##phase", "Running", UiTheme::kMuted,
          UiLayout(anchor = float2(1.0f, 0.0f), offset = float2(-24.0f, 24.0f)))

// Модальное окно: затемнение на весь экран + окно по центру.
Ui::Backdrop("##pause", UiTheme::kPauseCurtain) {
    Ui::Panel("##menu", UiTheme::kPausePanel, UiLayout(anchor = float2(0.5f, 0.5f), spacing = 12.0f)) {
        Ui::Label("##title", "Paused", UiTheme::kTitle)
        Ui::Button(UiTheme::kPrimaryButton, "##resume", "Resume", @@OnResume)
    }
}

// Две колонки в Row: grow — доля, поэтому по 0.5.
Ui::Row("##cols", UiStyle(), UiLayout(size = float2(Ui::ViewportSize().x, 0.0f), spacing = 16.0f)) {
    Ui::Column("##left", UiTheme::kHudPanel, UiLayout(grow = float2(0.5f, 0.0f))) { /* ... */ }
    Ui::Column("##right", UiTheme::kHudPanel, UiLayout(grow = float2(0.5f, 0.0f))) { /* ... */ }
}
```

`Ui::Backdrop` — это полноэкранный слой: рисует фон и **забирает указатель**, поэтому клики не
достаются экрану под ним, а виджеты внутри него работают. Так делаются модальные окна.

### Как проверять вёрстку

1. Запустите Play (F5) в редакторе и посмотрите на HUD в `SceneGameView`; панели **Screens**
   больше нет, Edit-превью игровых экранов не рисует.
2. `Ui::DebugRect("##hud/##fire")` печатает итоговый прямоугольник узла — быстрый способ
   понять, почему «не там». Для экрана в стеке соль слоя входит в id; `UiSystem::DebugRect`
   ищет без соли, поэтому проверяйте виджет в обычном `Ui::Frame`.
3. Держите в голове порядок: сначала родитель получает место, потом дети раскладываются внутри
   его `padding`-коробки.

Стиль и layout независимы: `UiStyle` — как выглядит, `UiLayout` — где стоит и сколько места
занимает.

## Стили и тема

`UiStyle` — структура с sentinel-полями: отрицательное число и пустая строка означают «здесь не
задано». Поэтому `UiStyle(color = kAccentHot)` задаёт один цвет, а не весь стиль.
`MergeStyle(base, over)` накладывает `over` на `base`; `ResolveStyle(kind, style)` сначала
берёт тему для вида виджета, потом накладывает переданный стиль и заполняет оставшиеся
sentinel-поля значениями по умолчанию.

`UiTheme` — по одному стилю на вид: `panel`, `text`, `button`, `bar`, `slider`, `checkbox`,
`image`. Игра ставит тему явно в `GameStart` (и повторно после горячей перезагрузки):

```das
def GameStart() {
    Ui::SetTheme(kTheme)   // UiTheme(panel = UiStyle(...), button = UiStyle(...), ...)
}
```

`SetTheme` накладывает тему на встроенную тему движка: незаданные виды и поля остаются
движковыми. Значит тема может переопределить только `button`, и панели при этом не потеряют
фон. `Ui::Theme()` возвращает то, что реально применяется, — удобно для тестов.

Порядок разрешения — от общего к частному: **тема → именованный стиль → конкретный виджет**.
Именованные стили (`UiTheme::kMuted`, `kHpBar`, `kPausePanel`) читаются экраном как обычные
значения и описывают только отличие от темы.

Что живёт в теме, а что в разметке: цвет, радиус, толщина рамки, размер текста, поля внутри,
длительность анимации, имена звуков — тема; `anchor`, `offset`, `spacing`, `size`, `grow`,
порядок детей — разметка.

### Шаблоны кнопок

`UiButtonTemplate` — стиль + стиль подписи + подпись по умолчанию + размер/layout.
`ButtonTemplate(base, over)` наследует: дочерний шаблон переопределяет только то, что задал.

```das
let public kDangerButton = ButtonTemplate(
    kPrimaryButton,                                  // наследует паддинги, радиус, звуки, текст
    UiButtonTemplate(style = UiStyle(color = kDanger, hover_color = kDangerHot), text = "Take damage")
)
```

Вызовы: `Ui::Button("##id", @@Action)`, `Ui::Button("##id", "Label", @@Action)`,
`Ui::Button(tpl, "##id", @@Action)`, `Ui::Button(tpl, "##id", "Label", @@Action)`,
`Ui::ButtonData(tpl, "##id", "Label", @@ActionData, data)`.

## Текстуры

`Ui::ImageTexture(id, guid, size, style)` рисует текстуру по **guid ассета** и не требует файла
материала: `UiSystem` собирает материал один раз из того же шейдера, что и текст, и привязывает
картинку туда, где у текста лежит атлас шрифта. Команда не появляется, пока текстура не
загрузилась, поэтому кадр не ломается на старте.

Экран не держит guid в коде: у каждого экрана есть свой бандл
(`game/data/bundles/<screen>.bundle`), который хранит `ключ -> guid`. Экран получает карту
алиасов и называет ключ:

```das
// ScreenHud.das
def public Draw(assets : AssetMap) {
    Ui::ImageTexture("##logo", assets.Texture("logo"), float2(24.0f, 24.0f))
    Ui::ImageTexture("##dim", assets.Texture("logo"), float2(64.0f, 64.0f),
                     UiStyle(color = float4(1.0f, 1.0f, 1.0f, 0.5f)))
}
```

Бандл загружается до показа экрана: `GameFlow::LoadScene` кладёт `hud.bundle` в тот же
`LoaderRequest`, что и сцену; `ui.bundle` — корневой, в нём шрифт. `AssetMap` — только
чтение зарегистрированной таблицы: UI сам никогда не просит ресурс, а непринесённая
текстура просто не рисуется и один раз пишет ошибку в лог.

- `style.color` — множитель цвета (по умолчанию белый; альфа тоже множитель), `size` — размер
  в пикселях цели;
- guid пишется один раз — в `assets`-таблице бандла (`ref = "guid:<id>"`), рядом с
  `kind = "texture"`. Ключ (`"logo"`) — то, что называет экран; путь и `.meta` в коде не
  нужны. Билд берёт ассеты из `assets` бандлов и кладёт их в common-пак, поэтому отдельного
  списка UI-текстур в C++ больше нет;
- настройки импорта (`format`, `generate_mips`, `max_size`, `filter`, `wrap`) лежат в `.meta`
  ассета, панель **Import Settings** показывает их для выбранного в Asset Browser файла, а
  `tools/agent/texture-probe.sh` проверяет запекание без редактора. Инструкция —
  `game/assets/ui/README.md`.

`Ui::Image(id, path, size)` остаётся для материала: когда картинка настраивается в
`game/data/**/*.mat` и её же использует 3D, материал — общий ресурс. Материал тоже перечислен
в бандле экрана (`kind = "material"`, `ref` — авторский путь `.mat`), а `Ui::MaterialFor`
только читает готовый ресурс из кеша.

## Шрифты и материалы

`UiStyle.font` и `UiStyle.material` — не guid, а **ключи карты ассетов экрана**. Тема
ссылается на шрифт ключом (`font = "font/body"`), а бандл экрана (или его родитель
`ui.bundle`) хранит `ключ -> guid:<id>`:

```das
// ui.bundle (корень)
{ name = "font/body", kind = "font", ref = "guid:7732110565556845333" }

// hud.bundle (ребёнок)
parent = "data/bundles/ui.bundle"
{ name = "logo", kind = "texture", ref = "guid:14429000468236573201" }
```

`UiSystem::FontMaterial(font_id)` строит материал текста из базового шейдера и атласа
шрифта; `TextureMaterial` — то же для картинки. Базовый материал UI фиксирован
(`UiConfig.material_path`), грузится boot-запросом как ресурс и не перечисляется в бандле.
Экран получает ключи из `AssetMap`; ни путь, ни guid в разметке не нужны. Шрифт можно
переопределить в бандле экрана тем же ключом — ребёнок перекрывает родителя.

## Свои виджеты

Виджет-композиция — обычная функция над примитивами `tryengine/Ui`. Три правила держат её
переиспользуемой: id приходит параметром, и локальные id детей живут под ним (две копии под
разными родителями не конфликтуют); своего состояния нет — значения приходят аргументами,
изменения уходят через `@@`/`var`; своих цветов нет — только стили темы. Пример —
`game/scripts/UiWidgets.das`: HUD и экран паузы собираются из одних `StatRow`/`MeterRow`, но
это разные экраны.

## Экраны

Экран — функция `def public Draw(assets : AssetMap)`. Никакого реестра и никаких строковых
имён: движок не знает, какие экраны существуют, а экран опознаётся указателем на функцию и
хранит дескриптор карты ассетов своего бандла.

- `Ui::ScreenRef(build = @@Draw, assets = map)` — значение: указатель + карта;
- `Ui::Screen(ref, layer)` — нарисовать экран на текущем месте (внутри `Frame`/другого экрана);
- `Ui::FrameScreen(ref)` — весь кадр: `Begin` + экран + `End`;
- `Ui::ScreenStack` — `Show`/`Push`/`Pop`/`Remove`/`Has`/`Top`/`Draw` по `ScreenRef`.

### Активный экран и стек

В движке нет «активного экрана» и нет глобального стека: `Ui::ScreenStack` — обычное значение,
которым владеет игра. Политика — что показать и когда — тоже в игре:
`game/scripts/GameScreens.das` (стек никогда не пустой, `Show` заменяет всё, `Push` кладёт
слой, `Pop` снимает верхний, `Has` сравнивает указатель).

```das
var stack : Ui::ScreenStack

stack.Show(Ui::ScreenRef(@@BuildHud, hud_assets))   // заменить стек
stack.Push(Ui::ScreenRef(@@BuildShop, shop_assets)) // положить поверх
stack.Pop()                                          // снять верхний
stack.Remove(@@BuildShop)                            // снять конкретный
stack.Has(@@BuildShop) : bool
stack.Top() : ScreenRef

Ui::Frame() {
    stack.Draw()     // порядок массива = порядок отрисовки
}
```

`Push` не добавляет слой, который уже открыт (две копии экрана объявили бы одинаковые id).
Номер слоя подмешивается в id узлов, поэтому одинаковый локальный `##shared` в двух слоях —
два разных узла. `GameScreens::Show`/`Push` принимают `ScreenRef`; `GameUi` и `ScreenHud` —
единственные модули, которые видят указатели на все нужные экраны.

### Режимы: игра, пауза, превью

| Режим | Кто объявляет кадр | Ввод | Побочные эффекты |
| --- | --- | --- | --- |
| Игра (`game_client`) | `GameUiFrame` каждый кадр | есть | есть |
| Play | `GameUiFrame` каждый кадр | есть | есть |
| Pause в редакторе | никто: кадр не объявляется | нет | нет |
| Edit | редактор, пустой кадр | нет | нет |

- **Pause** — пауза всей игры, UI включён. Редактор не объявляет UI-кадр, проход
  перерисовывает последний список команд: картинка замирает, указатель ничего не задевает.
  `Step frame` объявляет один кадр и шагает мир/UI на 1/60 с.
- **Edit** — игры нет и панели **Screens** больше нет: редактор объявляет пустой кадр
  (`Ui::Begin/End`), чтобы на вьюпорте не остался HUD от прошлого Play. `Ui::SetPreviewMode`
  остаётся для собственных проверок (hover/press работают, действия/звуки/записи в `var`
  подавлены), но игровые экраны в Edit не рисуются.

## Интеграция в игру

Точка входа — `[export] GameUiFrame()` в `game/scripts/Game.das` (её вызывает и `game_client`,
и редактор). Она объявляет UI каждый кадр на своём клоке и **не входит в `GameUpdate`**:

- `game_client` вызывает `EngineUpdate` → `GameUiFrame` → `GameUpdate` каждый кадр;
- редактор вызывает `GameUiFrame` в Play, в том числе **на паузе** (`Pause` замораживает
  `game_clock` и пропускает `GameUpdate`, но не UI): меню паузы остаётся живым и кликабельным
  над замороженной сценой;
- в Edit игра не запущена: пустой кадр, без экранов.

`GameStart` ставит тему, зовёт `GameFlow::Start()` (физика) и `GameUi::Start()`: boot-запрос
`main_menu.bundle` + базовый материал UI, по callback — `ScreenRef` меню. `GameFlow::LoadScene`
кладёт в запрос сцену и `hud`/`pause`/`shop` бандлы, по callback — `ScreenHud::Show(maps)`.
`GameUi::Frame()` синхронизирует слой паузы с флагом клока и рисует стек.

`GameUiFrame`/`Ui::Frame` не должны зависеть от состояния загрузчика или мира: их зовут и до
`GameStart`. Экраны читают глобальные переменные модуля, у которых есть разумные значения по
умолчанию.

## Ввод

`Ui::SetInputViewport(origin, size, hovered)` вызывается каждый кадр владельцем вьюпорта
(редактор — панелью `SceneGameView`, игра — не вызывает: вьюпорт на всё окно). `hovered = false`
отключает и hover, и клики. `Ui::ConsumesMouse()` говорит владельцу, что указатель занят
виджетом (редактор использует это, чтобы не запускать gizmo/выделение).

`InjectInput(pos, down, pressed, released)` подменяет мышь — так работает headless-тест
`tools/agent/ui-smoke.sh`. `Ui::HotId()`/`Ui::ActiveId()` — диагностика состояния.

## Текст

Текст — обычная интерполяция строк: `"HP {int(hp)}"`. Перенос по словам включается, если у
узла задан `layout.size.x`; измерение кешируется по (текст, размер), кеш сбрасывается при
смене атласа шрифта. Один шрифт на UI, глифы — SDF-атлас из ассета `.ttf` (см.
`game/assets/fonts/README.md`).

## Двусторонняя связь

- код → UI: значения читаются прямо в объявлении (`"HP {hp}"`, `value` у `ProgressBar`);
- UI → код: `@@`-действия, `var`-параметры (`Slider`, `Checkbox`) и наблюдатели
  `Ui::WatchFloat/WatchInt/WatchBool/WatchString` для «изменилось ли с прошлого кадра»;
- звуки: имя лежит в стиле (`sound_hover`, `sound_press`, `sound_click`), UI отдаёт событие
  `Ui::OnSound(handler)`. Аудио-подсистемы в движке нет: обработчик по умолчанию печатает
  каждый путь один раз.

## Звук

UI не проигрывает звук, а называет событие. Имя лежит в стиле (`sound_hover`, `sound_press`,
`sound_click`), обработчик ставится один раз:

```das
def private OnUiSound(path : string; node_id : uint64) {
    // path: "ui/hover", "ui/click", ...; node_id — узел, на котором событие случилось
}

Ui::OnSound(@@OnUiSound)
```

События приходят на **каждое** наступление: наведение — на вход на виджет (смена hot id),
press — на нажатие, click — на отпускание над тем же виджетом. Проверено headless-пробником:
три захода на кнопку дают три `hover`, два клика — два `press` и два `click`.

Обработчик по умолчанию печатает каждый путь **один раз за запуск** — это диагностика
(«событие вообще доходит»), а не лог. Поэтому в консоли `[UI SOUND] ui/hover` появляется
однажды, сколько бы вы ни наводили. Нужно каждое событие — поставьте свой `Ui::OnSound`.

Аудио-подсистемы в движке нет: чтобы звук зазвучал, нужен отдельный слой (загрузка клипов,
микшер, шины). UI-сторона к этому готова — имена уже в теме, `Backdrop`/меню ничего не знают о
звуке. В превью (`Ui::SetPreviewMode`) звуки подавляются: игра не запущена, и побочных
эффектов быть не должно.

## Профилирование

Зоны скрипта — `Ui.Frame` и `Ui.End` (объявление и layout+emit), GPU-строка — `Ui` (имя
прохода). Если кадр стал дорогим, сначала смотрите `Ui.End`: там layout и генерация команд.

## Ограничения v1

- нет поля ввода текста, прокрутки, клавиатурной навигации и фокуса;
- нет shaping/RTL, только кодовые точки из `ranges` ассета; несколько шрифтов поддержаны,
  но делят SDF-параметры одного прохода (одинаковый bake у всех);
- размеры — в пикселях цели, без DPI-масштабирования (в HiDPI UI мельче, чем в окне);
- прозрачность только через премультиплицированный блендинг; вложенные материалы — только
  `Image` (kind 2) и атлас шрифта;
- `UiPass` должен оставаться последним писателем `ForwardColor` в своём scope;
- бюджет команд — 1M вершин на кадр, дальше проход обрезает вывод.
